Practice Pack: 06 Transformers and LLMs#

Work this pack at least one day after reading the module. Write your answer before opening each solution; recognition is not retrieval.

1. Retrieval questions#

  1. What does tokenization determine?
Answer The sequence of integer inputs, which affects context length, cost, and what patterns the model can represent directly.
  1. What do Q, K, and V do in attention?
Answer Queries express what a position seeks, keys describe what positions offer, and values carry the information mixed into the output.
  1. What does causal masking prevent?
Answer A token from attending to future tokens during autoregressive training or generation.
  1. What does the key–value cache save?
Answer Previously computed keys and values so each new token need not recompute the whole prefix.
  1. Why is hallucination not solved by temperature alone?
Answer Sampling changes output randomness; it does not supply missing evidence or enforce truth.

2. Prediction exercises#

  1. If the context doubles and the key–value cache scales with tokens, what happens to cache memory?
Answer It roughly doubles, holding the other dimensions constant.
  1. If a future token is not masked during training, what shortcut can the model learn?
Answer It can look at the answer token itself or later tokens, producing an unrealistically easy training signal.
  1. If top-p is reduced, what general behavior should you expect?
Answer Sampling is restricted to a smaller probability mass, often reducing diversity but not guaranteeing factuality.

3. Debugging scenarios#

  1. Latency rises sharply only for long prompts. What should you inspect first?
Answer Prefill work, context length, key–value cache memory/pressure, batching, and truncation behavior.
  1. The model produces valid JSON that violates the requested schema. What boundary is missing?
Answer Schema validation and a repair/retry or constrained-decoding strategy at the structured-output boundary.
  1. A prompt injection in retrieved text causes a tool call. What design assumption failed?
Answer Retrieved content was treated as trusted instructions rather than untrusted data, and the tool boundary lacked authorization controls.

4. Short explanation prompts#

  1. Explain attention as information routing.
Answer Each position scores which other positions matter, normalizes those scores, and blends their value vectors into a context-sensitive representation.
  1. Explain prefill versus decode.
Answer Prefill processes the prompt and builds the cache; decode generates one token at a time using the cached prefix.
  1. Explain why evaluation must match the task.
Answer A general benchmark measures a different distribution and objective; a production evaluation must represent the decisions, users, and failure costs that matter.

5. Implementation task#

Implement the three-token attention calculation from the module with NumPy. Print the scores, masked weights, and output. Add one test proving future positions receive zero weight under a causal mask.

Do not open the rubric until you have a working attempt.

6. Rubric#

  • [ ] The scaling factor is applied before softmax.
  • [ ] The mask is applied before softmax.
  • [ ] Each attention row sums to one.
  • [ ] The test checks the causal property directly.
  • [ ] The output is compared with a hand-checked result.

7. Scoring#

  • 4 — Ready: answers are produced without notes, the implementation works, and the explanation names tradeoffs.
  • 3 — Practiced: one weak area remains; schedule a review in 7 days and redo that section.
  • 2 — Learning: revisit the module's first-pass path and retry the prediction/debugging sections tomorrow.
  • 1 — Not yet: ask for help or use the worked example, then restart with a smaller task.
